# SSPA-7: Secure Temporary Report Storage for Akamai Automation

## Overview

This PR implements and refines the **temporary report-storage capability for the Akamai automation workflow**.

The implementation is intentionally scoped only to SSPA-7 and provides a secure, execution-specific temporary workspace inside the active AAP Execution Environment.

The solution uses:

```text
/tmp/akamai-reports/<execution_id>/
```

for temporary report storage and validates storage configuration, filesystem availability, permissions, write/read/list access, metadata publication, and cleanup behavior.

The final deployment report is **not generated by SSPA-7**. SSPA-7 only prepares and validates temporary storage for downstream same-job consumers.

---

## What's New

### 1. PR Scope Cleanup

The PR is restricted to SSPA-7 temporary report-storage changes only.

Unrelated functionality is not part of this PR, including:

```text
ServiceNow validation
CTASK update
unrelated playbooks
unrelated role-dispatcher imports
unrelated collection changes
```

SSPA-7 is invoked explicitly using:

```yaml
tasks_from: report_storage
```

instead of being automatically executed through unrelated role-dispatcher logic.

### 2. Dedicated Execution-Specific Workspace

Instead of placing files directly under shared `/tmp`, the implementation now uses:

```text
/tmp/akamai-reports/<execution_id>/
```

This isolates concurrent executions and provides a controlled temporary workspace for each AAP execution.

### 3. Secure Directory and File Permissions

Private execution:

```text
Directory mode: 0700
File mode:      0600
```

Approved shared-group execution:

```text
Directory mode: 0750
File mode:      0640
```

The implementation validates both the configured permission contract and the resulting filesystem ownership/mode.

### 4. Protected Path and Identifier Validation

Execution IDs used in filesystem paths are restricted to safe characters:

```text
A-Z
a-z
0-9
.
_
-
```

Unsafe values containing traversal/path separators are rejected before workspace provisioning.

The resolved workspace is also validated to remain inside the approved temporary storage root.

### 5. Shared Logging Context

Logging context is resolved once and reused across all report-storage tasks.

The context includes:

```text
request_id
execution_id
environment
actor
triggered_by
timestamp
```

For deployed AAP execution:

```text
actor        = akamai_version_push.report_storage
triggered_by = actual AAP launcher
```

This clearly separates the automation component from the user who launched the job.

### 6. Environment Protection

For deployed AAP runs, supported environments are:

```text
dev
rnd
qa
prod
```

`test` and `local` are allowed only when explicit standalone/test mode is enabled.

The deployed environment is expected to come from protected inventory or fixed Job Template configuration rather than unrestricted survey input.

### 7. Request and Execution ID Protection

Integrated execution requires the shared workflow request ID and execution context.

Typical AAP execution identity:

```text
awx_job_id
```

Generated local fallbacks are allowed only for explicit standalone/local testing.

### 8. Real Write / Read / List Verification

Normal execution performs real filesystem verification:

```text
Create hidden probe
      ↓
Verify WRITE
      ↓
Verify file permissions
      ↓
Verify READ and content
      ↓
Verify LIST
      ↓
Remove probe
```

The hidden probe lookup explicitly uses:

```yaml
hidden: true
```

because the verification artifact begins with `.`.

### 9. Check Mode Semantics

Check Mode is handled separately from a normal run.

Check Mode validates configuration only and must publish:

```yaml
configuration_validated: true
storage_verified: false
workspace_exists: false
report_exists: false
check_mode: true
```

No real filesystem write/read/list verification should occur in Check Mode.

### 10. Truthful Published Metadata

SSPA-7 no longer publishes metadata that could imply that the final deployment report already exists.

Normal successful storage validation publishes information such as:

```yaml
report_storage:
  base_root: "/tmp"
  root: "/tmp/akamai-reports"
  workspace_path: "/tmp/akamai-reports/<execution_id>"
  configuration_validated: true
  storage_verified: true
  workspace_exists: true
  report_exists: false
  file_mode: "0600"
  directory_mode: "0700"
  ephemeral: true
  same_job_only: true
  separate_job_transfer_required: true
  cleanup_required: true
  cleanup_task: "report_storage_cleanup"
  final_report_naming_owner: "downstream_report_generation"
  audit_filename_owner: "common_logging"
```

`report_exists` remains `false` because SSPA-7 does not generate the final report.

### 11. Temporary Storage Lifecycle

The implementation documents that `/tmp` is available only inside the active AAP Execution Environment lifecycle.

Supported direct consumption:

```text
same AAP job
    ↓
later task reads workspace directly
```

Not guaranteed:

```text
Job A creates /tmp file
    ↓
Job A ends
    ↓
Job B expects the same file
```

Separate jobs require an approved transfer/persistent-storage mechanism.

### 12. Explicit Cleanup

A dedicated cleanup task is provided:

```text
report_storage_cleanup.yml
```

The workspace is deleted only after all same-job downstream consumers have completed.

The intended lifecycle is:

```text
prepare storage
      ↓
generate report
      ↓
consume/deliver report
      ↓
cleanup workspace
```

Cleanup should preferably be invoked from an `always` section in the integrated workflow.

### 13. common_logging Integration

Existing shared logging mechanisms are retained:

Successful events:

```yaml
tasks_from: log_event
```

Terminal failures:

```yaml
tasks_from: fail_with_error
```

No separate logging framework is introduced.

### 14. Task File Refactoring

The previous large storage implementation was split by responsibility:

```text
report_storage.yml
report_storage_context.yml
report_storage_validate.yml
report_storage_provision.yml
report_storage_verify.yml
report_storage_publish.yml
report_storage_cleanup.yml
```

This makes validation, provisioning, I/O verification, metadata publication and cleanup independently reviewable.

### 15. Documentation and Tests

Added documentation covering:

```text
implementation details
AAP QA validation
same-job lifecycle and downstream usage
technical-lead review changes
```

Added executable test coverage for:

```text
normal storage contract
Check Mode contract
metadata semantics
permissions
path safety
cleanup
common_logging behavior
```

## Error Codes

| Error Key | Category | Description |
|---|---|---|
| `REPORT_STORAGE_CONFIG_INVALID` | `validation` | Invalid storage root, path, identifier or permission contract |
| `REPORT_ACCESS_GROUP_INVALID` | `validation` | Configured protected access group is unavailable/invalid |
| `REPORT_STORAGE_UNAVAILABLE` | `infrastructure` | Temporary storage/workspace cannot be provisioned or validated |
| `REPORT_STORAGE_WRITE_FAILED` | `infrastructure` | Probe write or permission verification failed |
| `REPORT_STORAGE_READ_FAILED` | `infrastructure` | Probe read/content verification failed |
| `REPORT_STORAGE_LIST_FAILED` | `infrastructure` | Hidden probe list verification failed |
| `REPORT_STORAGE_CLEANUP_FAILED` | `infrastructure` | Execution-specific workspace cleanup failed |

Canonical numeric error-code mapping remains owned by the shared `common_logging` role.

## Notes

- Storage is intentionally **ephemeral**.
- SSPA-7 does not implement persistent retention.
- SSPA-7 does not generate the final deployment report.
- SSPA-7 does not send email.
- SSPA-7 does not own the final deployment-report filename.
- `common_logging` owns audit filename/rendering behavior.
- The later report-generation task owns final report content/path.
- Direct `/tmp` consumption is supported only within the same AAP job/Execution Environment.
- Cross-job report transfer requires an approved future mechanism.
- The access group and deployed environment should come from protected automation configuration.
- ServiceNow and CTASK changes must remain outside this PR.
